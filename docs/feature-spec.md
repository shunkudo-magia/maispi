# 機能仕様・会員登録の検討（草案）

> 追加実装予定の機能と、会員登録に関する検討事項をまとめた **草案** です。各項目はMTGで仕様・優先度を確定します。
> プラットフォーム: 直近は **Webメディア（Vercel）**、将来は **RN/Expoアプリ** も対象（[併記方針](./README.md)）。

## 1. 追加実装する機能

| # | 機能 | 概要 | ログイン要否 | 動的バックエンド要否 |
|---|------|------|:--:|:--:|
| 1 | 匿名コメント欄 | 記事に対する匿名コメント投稿・表示 | 不要（匿名） | **必要**（保存・表示） |
| 2 | いいね機能 | 記事への「いいね」カウント | 任意 | **必要**（カウント保存） |
| 3 | リンクをコピー | 記事URLをクリップボードにコピー | 不要 | 不要（フロントのみ） |
| 4 | SNSシェア | X / LINE / Instagram 等へのシェア | 不要 | 不要（フロントのみ） |

### 1-1. 匿名コメント欄
- 投稿は匿名（名前任意）。
- **要検討**: 投稿の保存先（DB）、スパム/誹謗中傷対策、NGワード、通報・削除フロー、表示順（新着/人気）、文字数制限。
- スピリチュアル領域のため **不適切投稿のモデレーション体制** が必須（[インフラ洗い出し 6](./infra-launch-checklist.md)のCS窓口）。

### 1-2. いいね機能
- 記事単位のカウント。
- **要検討**: 重複防止（IP/Cookie/会員）、リアルタイム反映、DB設計。会員ログインと紐づけるか。

### 1-3. リンクをコピー
- フロントのみで完結（Clipboard API）。最も実装が軽い。

### 1-4. SNSシェア
- 各SNSの共有導線。**要検討**: 対応SNS、OGP画像/タイトル/説明の設定（記事ごとのメタ）。

> 実装難易度: **3・4（フロントのみ）は早期に実装可。1・2 はバックエンド/DBが必要**なため、サーバ方針（[インフラ洗い出し 2](./infra-launch-checklist.md)）の決定が前提。

## 2. 会員登録の検討

会員登録は **要検討事項が多い** ため、MTGで方針を決める。

### 2-1. 解放機能（会員になると何ができるか）
- 想定: プレミアム記事/診断の閲覧、いいね・コメントの履歴、パーソナライズ（生年月日・月齢連動）など。
- **要決定**: 無料/有料の線引き、会員限定で「解放」するコンテンツ・機能の範囲。

### 2-2. セキュリティ
- **要検討**:
  - 認証方式（メール+パスワード / SNSログイン / LINEログイン / マジックリンク 等）
  - パスワード保管（ハッシュ化）、セッション管理
  - 個人情報の取り扱い（プライバシーポリシーとの整合 → [法務](./infra-launch-checklist.md)）
  - 不正ログイン対策、退会・データ削除フロー

### 2-3. DB（データベース）
- **要検討**:
  - 保存データ: 会員情報、コメント、いいね、診断履歴 など
  - DBの選定（マネージドDB / BaaS（Firebase・Supabase等） / 自前）
  - バックアップ・個人情報保護の要件
  - サーバ方針（[インフラ洗い出し 2](./infra-launch-checklist.md)）と一体で決定

## 3. 優先度（草案）

| フェーズ | 機能 | 理由 |
|----------|------|------|
| ローンチ時(6/12)に出せる | リンクコピー / SNSシェア | フロントのみ・「見た目重視」の合格ラインに合う |
| ローンチ後 早期 | 匿名コメント / いいね | DB・モデレーション体制の整備が必要 |
| 別途検討 | 会員登録（解放/セキュリティ/DB） | 設計・法務・運用体制の検討が必要 |

> 上記は提案。**6/12時点で動的機能をどこまで出すか**は[インフラ洗い出し](./infra-launch-checklist.md)とあわせてMTGで確定。
