# 記事企画ルール（草案）

> **Webメディア（直近ローンチ）** と **RN/Expoアプリ（将来）** の両トラックを対象にした **草案** です。`（要確認 / MTGで確定）` 項目はMTGで確定します。
> 根拠: Drive `maisupi-article-plan-30-v3.xlsx`（30記事企画マスター）、`src/lib/cms/*`（アプリ側型定義）。

## 1. Webメディアの企画体系（直近の本命）

記事企画マスター（`article-plan-30-v3`）に基づく実運用の体系。

### 企画単位
- **月号（M1, M2 …）** 単位で企画。初号は **M1 = 30記事** を計画。
- **特集4軸**（4本のマスター特集）を軸に記事を展開。
- 記事種別 **HERO / HUB / HELP**（SEO役割）を各記事に付与。
  - HERO: 集客の旗艦記事 / HUB: テーマの中核 / HELP: 検索ニーズに応える実用記事。

### カテゴリ（記事プラン準拠）
- 恋愛 / 人間関係 / 金運 ／（中カテ・小カテで細分: 婚活・告白・祈願・復縁・家族・貯金 等）
- ※ ビジュアル方針は[デザイン・ブランド](./design-branding.md)のカテゴリ別パレット参照。

### 著者制
- 記事は **著者名義**で執筆（例: 藤本環 / 星野澪 / 神崎和 / 白川珠代）。
- ポジション調整: 神崎和ポジは差し替え2本企画（魔除け廃止→浄化・縁切りに再振り）〆6/9。

### 1記事あたりの企画項目（マスターの列）
タイトル仮 / ターゲット読者 / コンプレックス軸 / 読もうとするインサイト（感情・状態）/ 目的・対象（自分・友人・家族・他人・噂）/ **読後感（罪悪感なき他責帰結）** / 伝えたいこと / **構成案（H2見出し）** / アイキャッチ画像プロンプト / 本文画像プロンプト×2。

> 企画の型: 「ターゲットのコンプレックス」→「読むインサイト」→「読後感（他責で罪悪感を残さない着地）」を必ず設計する。

## 2. アプリ側のコンテンツ構造（将来トラック / microCMS前提）

RN/Expoアプリは microCMS 連携を実装済み（`src/lib/cms/types.ts`）。CMS利用は**未確定**（[インフラ洗い出し](./infra-launch-checklist.md)）。

- **特集（Feature）** → 複数の **記事（Article）** の2階層。
- `Feature`: `id / title / category / subtitle(例:"2025年7月号") / coverImage?`
- `Article`: `id / title / body(richtext→HTML) / category / featureId / thumbnail?`
- アプリ側カテゴリキー: `love / money / family / body / work / spirit`（`src/constants/colors.ts`）。
- ⚠️ **Webメディアのカテゴリ（恋愛/人間関係/金運…）とアプリのキー（love/money…）の対応づけ**は要整理。

## 3. 企画フロー（草案）
1. 月号テーマ設定（季節・月相・トレンド）
2. 特集4軸へ割当、HERO/HUB/HELPの役割設計
3. ターゲット/インサイト/読後感の設計（マスター列を埋める）
4. 著者アサイン → 執筆（[執筆ルール](./writing-guidelines.md)）
5. 画像生成（プロンプト→fal.ai採用カット）
6. 公開（Web: Vercel / アプリ: CMS方針次第）
